# Географическая викторина — проектирование

## 1. Идея и ценность

**Что это:** интерактивная веб-викторина, где игрок угадывает местоположение
городов и достопримечательностей на карте мира. Кликает по карте — система
считает расстояние до правильной точки, начисляет очки за точность и скорость,
показывает правильный ответ.

**Ценность:** обучение через игру. Мгновенная обратная связь, соревновательный
элемент (таблица лидеров), простая механика — кликнул и получил очки.

## 2. Пользовательские сценарии (User Stories)

### Сценарий 1 — базовый игровой цикл
> Как игрок, я хочу запустить викторину, увидеть вопрос и карту, кликнуть
> в предполагаемое место и мгновенно получить очки.

**Как работает:** игрок вводит имя → выбирает режим → видит вопрос и карту →
кликает → подтверждает → получает очки, правильный ответ, линию от клика до
цели → переходит к следующему вопросу.

### Сценарий 2 — точность и скорость
> Как игрок, я хочу получать больше очков за точные и быстрые ответы.

**Как работает:** до 5000 очков за точность (экспоненциальная зависимость
от расстояния) × до 1.5 за скорость.

### Сценарий 3 — соревнование
> Как игрок, я хочу видеть таблицу лидеров, чтобы сравнивать результаты.

**Как работает:** после игры результат сохраняется с именем игрока.
На финальном экране — топ-10.

## 3. Функциональные требования

### Обязательные

**Фронтенд:**
- Экран старта: имя + выбор режима + кнопка «Начать».
- Экран игры: вопрос, карта, таймер, счёт, прогресс.
- Клик по карте → маркер → подтверждение ответа.
- Показ результата: очки, правильный ответ, линия от клика до цели.
- Экран итогов: суммарный счёт + таблица лидеров.
- Загрузка вопросов без перезагрузки страницы.

**Бэкенд:**
- Выдача случайных вопросов.
- Приём ответа, подсчёт очков по формуле гаверсинусов + бонус за скорость.
- Сохранение результатов в БД.
- Выдача таблицы лидеров.
- Валидация входных данных, обработка ошибок.

### Опциональные (реализованы)
- 3 режима: 10 вопросов, бесконечный, до первой ошибки.
- Таймер + бонус за скорость.
- Двойной клик — зум к точке.
- Подтверждение ответа (защита от случайных кликов).
- Подсказки (континент) с −30% к очкам.
- Прогресс-бар.

### Перспективы
- ИИ-генерация вопросов.
- Адаптивная сложность.
- Возможность предлагать свои вопросы.

## 4. API

Базовый URL: `http://localhost:8000/api`

### 4.1. GET /api/questions?limit=10

Возвращает N случайных вопросов. **Без координат** — иначе игрок подсмотрит
их через DevTools.

**Ответ 200:**
```json
[
  { "id": 1, "text": "Где находится Эйфелева башня?", "category": "landmark", "difficulty": "easy" }
]
```

### 4.2. POST /api/answer

**Тело:**
```json
{ "question_id": 1, "latitude": 48.8584, "longitude": 2.2945, "time_spent": 8.5 }
```

**Ответ 200:**
```json
{
  "question_id": 1,
  "correct_latitude": 48.8584,
  "correct_longitude": 2.2945,
  "correct_text": "Париж, Франция",
  "distance_km": 0.5,
  "base_score": 4995,
  "time_bonus": 1.2,
  "final_score": 5994
}
```

### 4.3. POST /api/games

**Тело:** `{ "player_name": "Анна", "score": 34500, "questions_count": 10 }`

**Ответ 201:** сохранённая игра с `id` и `created_at`.

### 4.4. GET /api/leaderboard?limit=10

**Ответ 200:**
```json
[{ "rank": 1, "player_name": "Иван", "score": 48200 }]
```

### 4.5. GET /api/hint/{question_id}

**Ответ 200:**
```json
{ "question_id": 1, "continent": "Европе", "category": "landmark" }
```

### 4.6. Обработка ошибок

Единый формат `{ "detail": "..." }`. Коды: 400 (невалидные данные),
404 (не найдено), 500 (внутренняя ошибка).

## 5. Модель данных

### Таблица `questions`
| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER PK | ID вопроса |
| text | TEXT | Текст вопроса |
| latitude | REAL | Правильная широта |
| longitude | REAL | Правильная долгота |
| correct_text | TEXT | Правильный ответ словами |
| category | TEXT | landmark / capital / city |
| difficulty | TEXT | easy / medium / hard |

### Таблица `games`
| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER PK | ID игры |
| player_name | TEXT | Имя игрока |
| score | INTEGER | Итоговый счёт |
| questions_count | INTEGER | Сколько вопросов |
| created_at | DATETIME | Дата |

## 6. Формула подсчёта очков

**Базовые очки за точность (экспоненциальная зависимость):**
```
base_score = round(5000 × exp(-distance_km / 500))
```

| Расстояние | Очки |
|---|---|
| 0 км | 5000 |
| 100 км | ~4093 |
| 500 км | ~1839 |
| 1000 км | ~676 |
| 2000 км | ~91 |

**Почему экспоненциальная:** честнее стимулирует точность. Линейная давала бы
слишком много очков за грубые ответы.

**Бонус за скорость:**
```
time_bonus = 1 + max(0, 15 - time_spent) / 30
```

- 15+ секунд → 1.0
- 5 секунд → 1.33
- Мгновенно → 1.5

**Итог за вопрос:** `final_score = round(base_score × time_bonus)`.

Расстояние — по формуле гаверсинусов (расстояние между двумя точками на сфере).

## 7. Технические решения

| Слой | Технология | Почему |
|---|---|---|
| Бэкенд | Python 3.12 + FastAPI | Простой синтаксис, Swagger из коробки, авто-валидация через Pydantic |
| ORM | SQLAlchemy | Стандарт, легко переключиться на PostgreSQL |
| БД | SQLite | Не требует установки сервера, файл в репозитории — проверяющему легко запустить |
| Фронтенд | React 18 + Vite + TypeScript | Современный стек, типизация, быстрый dev-сервер |
| Карта | react-simple-maps | SVG-карта без API-ключей и внешних сервисов |
| HTTP | axios | Проще, чем fetch, единый клиент с baseURL |

### Архитектура

```
┌───────────────┐  HTTP/JSON  ┌───────────────┐
│  React (SPA)  │ ──────────► │   FastAPI     │
│  react-simple │             │   SQLAlchemy  │
│  Tailwind     │ ◄────────── │   SQLite      │
└───────────────┘             └───────────────┘
  localhost:5173                 localhost:8000
```

Фронт и бэк — **отдельные приложения**, общаются по HTTP. CORS настроен на
origin `http://localhost:5173`.

### Почему НЕ Leaflet/Google Maps

Изначально был Leaflet, но у него обнаружились баги с размером контейнера
и неправильной инициализацией при SSR/Vite. Google Maps требует API-ключ
и привязку биллинга. `react-simple-maps` — SVG-карта без зависимостей от
внешних сервисов, работает мгновенно и стабильно.

### Безопасность

Координаты правильных ответов **не передаются на фронт** до момента ответа.
Это предотвращает читерство через DevTools. Проверка — на сервере.
